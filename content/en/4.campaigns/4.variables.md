# Variables and personalization

Variables allow you to automatically personalize your emails with each contact's information.

## Why personalize?

### Better open rate

A personalized subject gets 26% more opens than a generic subject.

### Better engagement

Personalized emails have a 2x higher response rate than generic emails.

### Professional image

Personalization shows that you've done your research and are addressing the right person.

## Writing a variable

A variable is written between curly braces: `{firstName}`. One or two braces work the same way: `{firstName}` and `{{firstName}}` give the same result. Square brackets do not work: `[firstName]` would be sent as-is to the recipient.

The safest way is the **+ Insert variable** menu, above the **Subject** and **Message** fields of the email. It adds the variable at the end of the text.

## Available variables

### Standard variables

| Variable | Description | Example |
|----------|-------------|---------|
| `{firstName}` | First name | John |
| `{lastName}` | Last name | Smith |
| `{fullName}` | First and last name | John Smith |
| `{email}` | Email | john@example.com |
| `{company}` | Company | Acme Corp |
| `{company.icebreaker}` | The company's icebreaker sentence | |
| `{company.subjectLine}` | The company's custom subject line (in the subject) | |
| `{phone}` | Phone | +1 555 123 4567 |
| `{address}`, `{city}`, `{postalCode}`, `{country}` | The contact's address, city, postal code, country | Paris |
| `{lienRdv}` | Link to your booking page, unique to each contact | |

There is no variable for the contact's job title or website.

### Sending mailbox

These variables refer to the mailbox sending this email (emails only, not LinkedIn):

| Variable | Description | Example |
|----------|-------------|---------|
| `{sender.domain}` | Domain of the mailbox, lowercase, e.g. `https://{sender.domain}/trial` | acme.com |
| `{sender.email}` | Address of the sending mailbox | jane@acme.com |
| `{sender.name}` | Display name of the mailbox, else your name | Jane Doe |

### Custom fields

Your custom fields (Settings → Personalization → Custom fields) are written with the `customField.` prefix followed by the **field name** as it was created:

| Variable | Example |
|----------|---------|
| `{customField.sector}` | Fintech |
| `{customField.company_size}` | 50-100 |
| `{customField.source}` | LinkedIn |

Writing `{sector}` without the prefix does not work: FluenzR then refuses to start the campaign ("unknown variables detected"). The **+ Insert variable** menu lists your custom fields already in the right form.

If a contact does not have this field, the variable is replaced with nothing: the recipient never sees `{customField.…}`. Plan a fallback text with the conditional blocks below.

## Using variables

### In the subject

Example: `{firstName}, quick question`

Result: "John, quick question"

### In the content

```text
Hello {firstName},

I noticed that {company} is expanding in the {customField.sector} sector.
```

### Insertion menu

1. In the email editor, click **+ Insert variable**, above the **Subject** or **Message** field
2. Select the variable to insert: it is added at the end of the text

## Fallback text when data is missing

There is no `variable|value` syntax. To plan a fallback text, use conditional blocks:

```text
{if firstName}Hello {firstName},{/if}{if !firstName}Hello,{/if}
```

- `{if variable}…{/if}`: the text appears only if the data is filled in
- `{if !variable}…{/if}`: the text appears only if the data is empty
- It also works with a custom field: `{if customField.sector}…{/if}`

Without a first name, "Hello {firstName}," simply becomes "Hello,".

> **Warning**
> Do not put a vertical bar inside a variable (`{firstName|there}`): FluenzR would read it as a random choice between the words "firstName" and "there".

## Formatting a variable

Add a filter after a vertical bar:

- `{firstName|uppercase}`: uppercase
- `{firstName|lowercase}`: lowercase
- `{firstName|capitalize}`: first letter in uppercase
- `{company|title}`: first letter of each word in uppercase
- `{firstName|trim}`: removes surrounding spaces

## Text variants

`{Hello|Hi}` (two options separated by a vertical bar) picks one of the options, always the same one for a given contact.

## Best practices

### Always plan a fallback

For data that is often empty, use an `{if}` / `{if !}` block to avoid emails with blanks.

### Check data quality

Before using a variable, ensure that:
- The field is filled for most contacts
- The data is clean (correct capitalization, etc.)

### Natural personalization

Avoid over-personalization that seems artificial. 1-2 variables per paragraph is enough.

### Test before sending

1. Use preview with different contacts
2. Send yourself a test email (see below)
3. Check cases where data is missing

#### Previewing on your real contacts

In the campaign email editor, the **Preview** button shows the message exactly as a
contact from your audience will receive it, with their real data: first name, company,
custom fields. The arrows, or the left and right keyboard keys, move through contacts
one at a time.

It is the fastest way to spot an empty field or a misspelled variable before the
campaign goes out.

When no list or contact is attached to the campaign yet, the preview falls back to
sample data. For a large audience, navigation covers the first 100 contacts, while the
real size stays on screen.

#### The test email

The **Send test** button sends the campaign to your inbox so you can see the real rendering. It is in two places:

- in the editor, in the email's panel, to test the email you are writing;
- on the campaign page (Campaigns → the campaign), to test the whole sequence.

In the test email, the subject starts with `[TEST]`, variables are filled with a fictional contact (John Doe, Test Company, Paris) and custom fields are empty. There is no unsubscribe link and no tracking, so the test is not identical to the real email at the footer.

## Template example

```text
Subject: {firstName}, question about {company}

{if firstName}Hello {firstName},{/if}{if !firstName}Hello,{/if}

I'm reaching out because {company} seems to perfectly
match the profile of companies we support.

Would you be available for a 15-minute exchange?

Best regards,
```

Do not write a signature or an unsubscribe link: the signature of the sending mailbox (Settings → Email accounts → the mailbox → General → Default signature) and the unsubscribe footer are added automatically to every email. There is no variable to place them.

## Troubleshooting

### Variable displayed as-is

If the variable displays instead of the value:
- Check the variable spelling
- For a custom field, check the `customField.` prefix
- Use the **+ Insert variable** menu rather than manual entry
- Do not use square brackets: `[firstName]` is not a variable

### Incorrect data

If "john" displays instead of "John":
- Clean your data at the source
- Use CSV import with clean data
- Manually correct important contacts
- Or add the `capitalize` filter: `{firstName|capitalize}`

### Empty variable

If nothing displays:
- Add a fallback text with `{if !variable}`
- Verify the field is not empty for this contact

### Launch is refused: "unknown variables detected"

The name between braces does not exist. Compare with the list above; for a custom field, add the `customField.` prefix.
