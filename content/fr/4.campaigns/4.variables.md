# Variables et personnalisation

Les variables vous permettent de personnaliser automatiquement vos emails avec les informations de chaque contact.

## Pourquoi personnaliser ?

### Meilleur taux d'ouverture

Un objet personnalisé obtient 26% d'ouvertures en plus qu'un objet générique.

### Meilleur engagement

Les emails personnalisés ont un taux de réponse 2x plus élevé que les emails génériques.

### Image professionnelle

La personnalisation montre que vous avez fait des recherches et que vous vous adressez à la bonne personne.

## Écrire une variable

Une variable s'écrit entre accolades : `{firstName}`. Une ou deux accolades fonctionnent de la même façon : `{firstName}` et `{{firstName}}` donnent le même résultat. Les crochets ne marchent pas : `[firstName]` partirait tel quel chez le destinataire.

Le plus sûr est de passer par le menu **+ Insérer variable**, au-dessus des champs **Sujet** et **Message** de l'email. Il ajoute la variable à la fin du texte.

## Variables disponibles

### Variables standard

| Variable | Description | Exemple |
|----------|-------------|---------|
| `{firstName}` | Prénom | Jean |
| `{lastName}` | Nom | Dupont |
| `{fullName}` | Prénom et nom | Jean Dupont |
| `{email}` | Email | jean@example.com |
| `{company}` | Entreprise | Acme Corp |
| `{company.icebreaker}` | Phrase d'accroche de l'entreprise | |
| `{company.subjectLine}` | Objet personnalisé de l'entreprise (dans le sujet) | |
| `{phone}` | Téléphone | +33 6 12 34 56 78 |
| `{address}`, `{city}`, `{postalCode}`, `{country}` | Adresse, ville, code postal, pays du contact | Paris |
| `{lienRdv}` | Lien de votre page de rendez-vous, propre à chaque contact | |

Il n'existe pas de variable pour le poste ni pour le site web du contact.

### Boîte d'envoi

Ces variables désignent la boîte qui envoie cet email (emails uniquement, pas LinkedIn) :

| Variable | Description | Exemple |
|----------|-------------|---------|
| `{sender.domain}` | Domaine de la boîte, en minuscules, par exemple `https://{sender.domain}/essai` | acme.com |
| `{sender.email}` | Adresse de la boîte d'envoi | jane@acme.com |
| `{sender.name}` | Nom d'affichage de la boîte, sinon votre nom | Jane Doe |

### Champs personnalisés

Vos champs personnalisés (Configuration → Personnalisation → Champs personnalisés) s'écrivent avec le préfixe `customField.` suivi du **nom du champ** tel qu'il est créé :

| Variable | Exemple |
|----------|---------|
| `{customField.secteur}` | Fintech |
| `{customField.taille_entreprise}` | 50-100 |
| `{customField.source}` | LinkedIn |

Écrire `{secteur}` sans le préfixe ne fonctionne pas : FluenzR refuse alors de lancer la campagne (« variables inconnues détectées »). Le menu **+ Insérer variable** propose vos champs personnalisés déjà sous la bonne forme.

Si un contact n'a pas ce champ, la variable est remplacée par du vide : le destinataire ne voit jamais `{customField.…}`. Prévoyez un texte de repli avec les blocs conditionnels ci-dessous.

## Utiliser les variables

### Dans l'objet

Exemple : `{firstName}, question rapide`

Résultat : "Jean, question rapide"

### Dans le contenu

```text
Bonjour {firstName},

J'ai vu que {company} se développe dans le secteur {customField.secteur}.
```

### Menu d'insertion

1. Dans l'éditeur de l'email, cliquez sur **+ Insérer variable**, au-dessus du champ **Sujet** ou **Message**
2. Sélectionnez la variable à insérer : elle est ajoutée à la fin du texte

## Texte de repli quand une donnée manque

Il n'existe pas de syntaxe `variable|valeur`. Pour prévoir un texte de repli, utilisez les blocs conditionnels :

```text
{if firstName}Bonjour {firstName},{/if}{if !firstName}Bonjour,{/if}
```

- `{if variable}…{/if}` : le texte n'apparaît que si la donnée est renseignée
- `{if !variable}…{/if}` : le texte n'apparaît que si la donnée est vide
- Cela marche aussi avec un champ personnalisé : `{if customField.secteur}…{/if}`

Sans prénom, « Bonjour {firstName}, » devient simplement « Bonjour, ».

> **⚠️ Attention**
> Ne mettez pas de barre verticale dans une variable (`{firstName|there}`) : FluenzR la lirait comme un choix aléatoire entre les mots « firstName » et « there ».

## Mise en forme d'une variable

Ajoutez un filtre après une barre verticale :

- `{firstName|uppercase}` : majuscules
- `{firstName|lowercase}` : minuscules
- `{firstName|capitalize}` : première lettre en majuscule
- `{company|title}` : première lettre de chaque mot en majuscule
- `{firstName|trim}` : retire les espaces autour

## Variantes de texte

`{Bonjour|Salut}` (deux options séparées par une barre verticale) choisit l'une des options, toujours la même pour un contact donné.

## Bonnes pratiques

### Toujours prévoir un repli

Pour une donnée souvent vide, utilisez un bloc `{if}` / `{if !}` afin d'éviter les emails avec des blancs.

### Vérifier la qualité des données

Avant d'utiliser une variable, assurez-vous que :
- Le champ est renseigné pour la majorité des contacts
- Les données sont propres (majuscules correctes, etc.)

### Personnalisation naturelle

Évitez la sur-personnalisation qui semble artificielle. 1-2 variables par paragraphe suffisent.

### Tester avant d'envoyer

1. Utilisez l'aperçu avec différents contacts
2. Envoyez-vous un email de test (voir ci-dessous)
3. Vérifiez les cas où des données manquent

#### L'aperçu sur vos contacts réels

Dans l'éditeur d'un email de campagne, le bouton **Aperçu** affiche le message tel que
le recevra un contact de votre audience, avec ses vraies données : prénom, entreprise,
champs personnalisés. Les flèches, ou les touches gauche et droite du clavier, font
défiler les contacts un à un.

C'est le moyen le plus rapide de repérer un champ vide ou une variable mal orthographiée
avant le départ de la campagne.

Quand aucune liste ni aucun contact n'est encore rattaché à la campagne, l'aperçu se
rabat sur des données d'exemple. Pour une grande audience, la navigation porte sur les
100 premiers contacts, la taille réelle restant affichée.

#### L'email de test

Le bouton **Envoyer un test** envoie la campagne dans votre boîte de réception, pour voir le rendu réel. Il se trouve à deux endroits :

- dans l'éditeur, dans le panneau de l'email, pour tester l'email que vous êtes en train d'écrire ;
- sur la page de la campagne (Campagnes → la campagne), pour tester toute la séquence.

Dans l'email de test, le sujet commence par `[TEST]`, les variables sont remplies avec un contact fictif (John Doe, Test Company, Paris) et les champs personnalisés sont vides. Il n'y a ni lien de désinscription, ni suivi : le test n'est donc pas identique à l'email réel sur le pied de page.

## Exemple de template

```text
Objet : {firstName}, question sur {company}

{if firstName}Bonjour {firstName},{/if}{if !firstName}Bonjour,{/if}

Je me permets de vous contacter car {company} semble
correspondre parfaitement au profil des entreprises que
nous accompagnons.

Seriez-vous disponible pour un échange de 15 minutes ?

Cordialement,
```

Ne rédigez ni signature ni lien de désinscription : la signature de la boîte d'envoi (Configuration → Comptes email → la boîte → Général → Signature par défaut) et le pied de désinscription sont ajoutés automatiquement à chaque email. Il n'existe pas de variable pour les placer.

## Résolution de problèmes

### Variable affichée telle quelle

Si la variable s'affiche au lieu de la valeur :
- Vérifiez l'orthographe de la variable
- Pour un champ personnalisé, vérifiez le préfixe `customField.`
- Utilisez le menu **+ Insérer variable** plutôt que la saisie manuelle
- N'utilisez pas de crochets : `[firstName]` n'est pas une variable

### Données incorrectes

Si "jean" s'affiche au lieu de "Jean" :
- Nettoyez vos données à la source
- Utilisez l'import CSV avec des données propres
- Corrigez manuellement les contacts importants
- Ou ajoutez le filtre `capitalize` : `{firstName|capitalize}`

### Variable vide

Si rien ne s'affiche :
- Ajoutez un texte de repli avec `{if !variable}`
- Vérifiez que le champ n'est pas vide pour ce contact

### Le lancement est refusé : « variables inconnues détectées »

Le nom entre accolades n'existe pas. Comparez avec la liste ci-dessus ; pour un champ personnalisé, ajoutez le préfixe `customField.`.
